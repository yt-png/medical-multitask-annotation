# 医学图像多任务标注数据流 需求文档

## 1\. 文档目的



本文档描述一套**本地化、可脚本化**的医学图像多任务标注数据流：在不搭建业务服务器的前提下，对同一批医学图像完成**图像分割（SEG）**、**目标检测（DET）**、**图像文本生成（CAP）三类标注，最终产出每张图像同时具备三类标注**的多任务数据集。



协作中的任务包分发与结果回传通过**网盘**完成；本数据流的代码范围覆盖预处理、任务包拆分、预标注格式统一、Label Studio 工作台与导入导出、返工结果覆盖、结果分类与最终合并等模块。**具体预标注算法与大模型调用暂不开发。**



---



## 2\. 背景与建设目标



### 2\.1 背景



医院侧提供带诊断信息的医学图像原始数据。业务需要构建一套可重复执行的标注流水线，对同一批图像分别完成三类任务标注，并在人工确认与返工闭环结束后，合并为统一的多任务标注数据集。



### 2\.2 建设目标



1. 建立清晰、可执行的多任务标注数据流（按模块拆分并可落地为代码）。

2. 保证三类任务在合并前**链路完全独立**。

3. 支持「算法/大模型预标注 → 人工确认/修改 → 返工闭环 → 三任务合并」的完整过程。

4. 现阶段只实现已明确部分；未确定算法/模型的预标注执行代码暂不实现。

    

### 2\.3 最终产物



**多任务标注数据集**：数据集中每一张图像都必须同时包含：



- SEG：分割 mask（以最终人工确认结果为准；未修改则保留预标注）

- DET：检测 bbox（同上）

- CAP：诊断/描述文本（同上）

    

并保留可追溯的身份标识与必要元信息（至少包括图像唯一 ID、任务包唯一 ID、人工确认状态、是否返工状态在最终合并前各轮次中的有效记录策略见返工规则）。



---



## 3\. 角色与职责



### 3\.1 数据处理人员



- 接收并预处理原始数据（图像与诊断文本绑定）。

- 按任务类型生成并拆分标注任务包。

- 通过网盘分发任务包、回收结果包。

- 对返工包汇总问题，组织线下讨论。

- 在三类任务全部无返工后，执行三任务结果合并，产出最终数据集。

    

### 3\.2 标注人员（按任务类型分工）



- 每人只处理**一种任务类型**的任务包（SEG 或 DET 或 CAP）。

- 从网盘下载任务包到本地。

- 对本任务执行预标注（现阶段人工/外部工具完成即可，平台暂不开发算法调用代码）。

- 将预标注转为统一导入格式，导入 Label Studio。

- 在自定义工作台中人工确认/修改，勾选「人工确认」「是否返工」。

- 导出结果并按返工标记分类后上传网盘。

- 对返工包执行二次及后续标注，再次导出上传。

    

### 3\.3 协作约束



- 不搭建用于任务分发/回收的业务服务器。

- 网盘传输环节**不要求、不编写**自动化传输代码。

    

---



## 4\. 输入与输出



### 4\.1 输入



原始数据集，至少包含：



|内容|当前约定格式|说明|
|---|---|---|
|原始医学图像|`.jpg`|每张图需可唯一标识|
|原始诊断文本|Excel（如 `.xlsx`/`.xls`）|需与图像一一对应|



### 4\.2 输出



多任务标注数据集：



- 粒度：按图像（以图像唯一身份标识对齐）

- 内容：每张图必须具备 SEG、DET、CAP 三类最终标注

- 质量门禁：进入最终合并前，该批三个任务的数据均应处于「无需再返工」状态

    

---



## 5\. 总体原则与硬性约束



### 5\.1 三任务独立链路



从「标注任务包拆分」开始，到「最终三任务合并」之前：



- SEG / DET / CAP 为**三条完全独立**的数据链路。

- 预标注、Label Studio 人工标注、导出分类、返工再标注均相互独立、互不影响。

- 任一任务的返工循环不得阻塞或改写另外两个任务的数据状态（除最终合并读取各自最终结果外）。

    

### 5\.2 人工结果优先



对单张图像、单任务：



- 若人工修改了预标注 → **以人工结果为最终结果**

- 若人工未修改预标注 → **以预标注结果为最终结果**

- 无论是否修改，均必须勾选「人工确认」，表示该样本经过人工处理，而非完全依赖自动预标注。

    

### 5\.3 开发范围边界



必须严格按本需求开展模块拆分与代码开发：



- **禁止**自行新增本文档未描述的功能。

- **禁止**在现阶段开发尚未确定的部分（尤其是具体预标注算法/大模型推理脚本）。

- 允许先定义并实现：统一预标注导入格式、转换接口/脚本骨架、Label Studio 配置与导入导出、返工覆盖、结果分类、最终合并等已明确部分。

    

### 5\.4 返工覆盖原则（补充需求，关键）



每次返工标注完成后导出时：



- **覆盖**该样本此前的标注结果；

- **覆盖**此前的「人工确认 / 是否返工」勾选信息；

- **只保留**本次返工得到的标注结果，以及本次勾选的「人工确认 / 是否返工」信息。

    

即：对同一图像、同一任务，平台侧只维护**当前最新一版**有效标注与有效勾选状态，不在结果包中并行保留历史多版本标注作为有效结果。

## 6\. 端到端业务流程



### 6\.1 流程总览



1. **预处理**：数据处理人员对原始图像与诊断文本做清洗绑定，为每张图生成唯一身份标识。  

2. **生成与拆分任务包**：按 SEG / DET / CAP 生成三类任务包；每张图对应三个任务包；每类任务包数据量等于拆分前图像总量；任务包自身绑定唯一身份标识；包内均含原始图像与原始诊断文本。  

3. **网盘分发**：将三类任务包分别发给对应任务标注员（无代码）。  

4. **本地预标注**（算法未定，暂不开发调用代码）：  

    - SEG：分割算法生成 mask  

    - DET：检测算法生成 bbox  

    - CAP：大模型 \+ 提示词生成诊断文本  

5. **预标注格式转换**：将异构预标注统一为 Label Studio 可导入格式。  

6. **Label Studio 人工确认**：导入原始图像、预标注、原始诊断文本；人工修改或确认；勾选「人工确认」「是否返工」。  

7. **导出**：从 Label Studio 导出本轮标注结果。  

8. **结果分类**：按「是否返工」拆成正常结果包与返工结果包。  

9. **网盘上传**：两类结果包均上传（无代码）。  

10. **返工问题处理**：数据处理人员下载后，总结返工问题并线下与标注员讨论。  

11. **返工再标注**：标注员将返工包重新导入 Label Studio（可见上一轮标注结果），完成二次标注后导出并上传。  

    - 导出时执行**覆盖策略**：只保留当前返工结果与当前勾选信息。  

12. **返工闭环**：若仍有需返工样本，重复「总结 → 讨论 → 再标注 → 覆盖导出 → 再分类上传」；直到该任务该批数据全部不需要返工。  

13. **三任务合并**：当本批图像的三个任务均全部无需返工后，数据处理人员合并三类最终结果，得到多任务标注数据集。

    

### 6\.2 状态口径（单任务、单张图）



建议业务状态理解为：



- `待预标注` → `已预标注待人工` → `已人工确认且无需返工` / `已人工确认且需返工`  

- 需返工样本进入：`返工中` → 再次导出后重新判定为无需返工或仍需返工  

- 每次返工导出后，旧状态与旧标注被新结果覆盖

## 7\. 功能模块详细需求



### 7\.1 数据预处理



**目标**：建立图像与诊断文本的一一对应，并为后续全链路提供稳定主键。



**功能要求**：



1. 为每张图像生成并绑定**唯一身份标识**（图像 ID）。  

2. 将图像与原始诊断文本记录一一对应绑定。  

3. 输出可供后续「任务包生成」使用的标准化预处理结果（至少包含：图像文件、对应诊断文本、图像 ID）。  

4. 当前输入形态：图像为 jpg；诊断文本来自 Excel。

    

**验收要点**：



- 不存在无 ID 图像、不存在图像与文本错配。  

- 同一批数据内图像 ID 唯一。

    

---



### 7\.2 生成并拆分标注任务包



**目标**：把同一批预处理数据拆成三类独立任务包，供不同标注员并行处理。



**功能要求**：



1. 为每个标注任务包生成并绑定**唯一身份标识**（任务包 ID）。  

2. 按标注任务类型拆分，得到三类任务包：SEG 包、DET 包、CAP 包。  

3. 「按任务类型拆分」**不是**把样本数量均分成三份；而是：  

    - 拆分前有 N 张图；  

    - 拆分后 SEG、DET、CAP 各自仍包含这 N 张图对应的任务数据。  

4. 三类任务包都必须包含：  

    - 原始图像  

    - 原始诊断文本  

    - 图像唯一身份标识（及任务包身份标识）  

5. 三类任务包自此进入独立链路，互不影响。

    

**验收要点**：



- 每类任务包样本数 = 预处理后有效图像数。  

- 包内字段完整，可供后续预标注与 Label Studio 导入使用。

    

---



### 7\.3 标注任务包分发



**说明**：通过网盘人工传输。



**约束**：



- 不涉及代码脚本，不搭建服务器。  

- 每个标注员只获得一种任务类型的任务包。

    

---



### 7\.4 图像预标注生成



**业务意图**（已明确）：



- SEG：用分割算法生成 mask  

- DET：用检测算法生成 bbox  

- CAP：用大语言模型与提示词生成诊断文本  

    

**现阶段开发约束**：



- 具体算法与大模型尚未确定，**本阶段不开发预标注执行代码**。  

- 后续确定算法/模型后，再按任务分别补齐预标注模块。  

- 当前数据流需预留：预标注结果进入「格式转换」模块的输入约定。

    

---



### 7\.5 预标注格式转换



**目标**：屏蔽不同算法/模型输出差异，保证 Label Studio 导入格式统一。



**功能要求**：



1. 针对同一任务、不同算法/大模型可能产生的不同数据格式与编码方式，提供统一转换能力。  

2. 现阶段即使算法未定，也必须先定义并固化：  

    - 三个任务各自最终用于 Label Studio 的**预标注导入统一格式**  

3. 转换后的数据应能与原始图像、原始诊断文本一并导入 Label Studio。  

4. 转换逻辑按任务独立（SEG/DET/CAP 各自转换，互不耦合）。

    

**验收要点**：



- 不同来源预标注经转换后，可被对应任务工作台稳定导入。  

- 转换失败时应可定位到图像 ID / 任务包 ID（具体报错形态以实现时最小必要为准，不扩展额外平台功能）。

    

---



### 7\.6 在 Label Studio 中进行人工标注确认



#### 7\.6\.1 导入内容（三任务共通）



导入 Label Studio 前，每条样本必须同时具备：



1. 原始图像  

2. 预标注结果（SEG: mask / DET: bbox / CAP: 模型生成文本）  

3. 原始诊断文本  

    

#### 7\.6\.2 自定义标注工作台



需通过代码/配置脚本自定义三类工作台。



**SEG 工作台**



- 必须展示：原始图像、预标注 mask、原始诊断文本  

- 标注员可修改预标注 mask  

- 必须提供两个复选框：  

    - **人工确认**（每张必勾）  

    - **是否需要返工**

        

**DET 工作台**



- 必须展示：原始图像、预标注 bbox、原始诊断文本  

- 标注员可修改预标注 bbox  

- 同样必须提供「人工确认」「是否需要返工」两个复选框

    

**CAP 工作台**



- 必须展示：原始图像、预标注生成的诊断文本、原始诊断文本  

- 标注员可修改预标注文本  

- 同样必须提供「人工确认」「是否需要返工」两个复选框

    

#### 7\.6\.3 复选框语义



1. **人工确认**  

    - 无论是否修改预标注，每张图像都必须勾选。  

    - 含义：该图已经过人工修改或人工确认，不是完全依赖算法/大模型预标注。  

        

2. **是否需要返工**  

    - 当标注员不确定当前标注是否正确时可勾选。  

    - 导出后据此将样本分入返工结果包。  

        

#### 7\.6\.4 结果判定规则



- 有人工修改 → 最终标注 = 人工修改结果  

- 无人工修改 → 最终标注 = 预标注结果  

- 上述最终标注仍需伴随本轮「人工确认 / 是否返工」勾选信息一并导出

    

---



### 7\.7 结果包导出与分类



**功能要求**：



1. 从 Label Studio 导出本轮全部已处理样本。  

2. 按每张图是否勾选「需要返工」分类，生成：  

    - **正常结果数据包**（未勾选返工）  

    - **需返工结果数据包**（已勾选返工）  

3. 两个数据包均通过网盘上传（上传过程无代码）。  

    

**验收要点**：



- 分类完整、不丢样本、不串包。  

- 导出内容包含当前有效标注结果及当前勾选信息。

    

---



### 7\.8 数据的返工标注（含覆盖补充）



#### 7\.8\.1 返工触发与线下协同



1. 数据处理人员下载正常包与返工包。  

2. 针对返工包总结标注过程问题，线下与标注人员讨论。  

3. 标注人员基于讨论结论，对返工包进行再次标注。

    

#### 7\.8\.2 返工导入要求



- 返工数据包重新导入 Label Studio 时，标注员**必须能看到上一轮标注结果**（作为本轮修改起点）。  

- 工作台能力与首轮一致（展示规则、可编辑性、两个复选框均保留）。

    

#### 7\.8\.3 返工导出覆盖规则（补充，必须实现）



每次返工完成后导出时，对同一图像、同一任务：



1. **覆盖旧标注结果**：仅保留当前这一轮返工后的标注结果。  

2. **覆盖旧勾选信息**：仅保留当前这一轮的「人工确认」「是否返工」勾选状态。  

3. 结果包中不应再把历史轮次标注或历史勾选作为并行有效结果保留。  

4. 若本轮仍勾选「需要返工」，则该样本继续进入新的返工包，进入下一轮闭环；上一轮结果已被本轮覆盖。  

5. 若本轮未勾选返工，则该样本进入正常结果包，其当前标注与当前勾选即为该任务该样本的最新有效结果。

    

#### 7\.8\.4 返工闭环结束条件（单任务）



对该批、该任务：持续返工直到**全部样本均不再需要返工**。



三任务各自独立满足该条件后，才允许进入最终合并。



---



### 7\.9 最终标注结果合并



**前置条件**：



- 本批图像的 SEG、DET、CAP 三条链路均已完成，且各自全部样本均无需再返工。

    

**功能要求**：



1. 按图像唯一身份标识对齐三类任务的最终有效标注。  

2. 合并得到多任务标注数据集。  

3. 合并后每张图像必须同时具备三个任务的标注；不允许缺任务样本进入最终集（缺任务应视为合并失败或需阻断并提示，不得静默丢弃字段）。  

    

**验收要点**：



- 最终集图像数与预期有效图像数一致（在三类均完成的前提下）。  

- 每条记录含完整三任务最终标注。

    

---



## 8\. 按任务拆分的数据对象理解



### 8\.1 图像级对象（全链路共用）



- 图像唯一 ID  

- 原始图像文件（jpg）  

- 原始诊断文本（来自 Excel 的对应记录）

    

### 8\.2 任务包对象



- 任务包唯一 ID  

- 任务类型：`SEG` \| `DET` \| `CAP`  

- 包内样本列表（每条含图像 ID、图像、原始诊断文本）

    

### 8\.3 单任务标注结果对象（当前有效版）



- 图像唯一 ID  

- 任务类型  

- 当前有效标注内容（mask / bbox / caption）  

- 当前「人工确认」状态  

- 当前「是否返工」状态  

- （实现时可含任务包 ID、导出轮次等必要追溯字段，但有效结果语义以“当前版覆盖”为准）

    

### 8\.4 导出分类对象



- 正常结果包：当前「是否返工」= 否  

- 返工结果包：当前「是否返工」= 是

|M8|网盘回传|否（人工）|无代码|
|M9|返工再导入与覆盖导出|是|可见上轮结果；导出只保留当前版|
|M10|三任务最终合并|是|每图三任务齐全|

## 10\. 非功能与实施约束



1. **本地优先**：标注员在本地完成预标注转换与 Label Studio 操作。  

2. **无业务服务端**：不因分发/回收需求搭建服务器。  

3. **可后续扩展预标注**：格式层先统一，算法层后接入。  

4. **严格控范围**：不扩展文档外功能（如在线任务管理台、自动网盘同步、质检看板等）。  

5. **一致性**：返工覆盖策略必须在导出与分类逻辑中同时生效，避免“界面已改、包内仍留旧结果”。

    

---



## 11\. 验收标准（整体）



1. 可用真实原始数据（jpg \+ Excel 诊断文本）跑通：预处理 → 拆三包 →（外部预标注）→ 格式转换 → Label Studio 人工确认 → 导出分类。
